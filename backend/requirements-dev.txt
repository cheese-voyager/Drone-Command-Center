# Seeder Drone: Drone Penebar Benih

Sistem drone penebar benih berbasis **Pixhawk + Raspberry Pi + Mission Planner**, dengan dashboard **web (React)** dan aplikasi **mobile (Flutter)** untuk memantau dan mengontrol drone secara real-time.

Repo ini berbentuk **monorepo**: backend, firmware/IoT, web, dan mobile ada dalam satu repository supaya perubahan API bisa dikoordinasikan dalam satu tempat.

## Fitur

- **Monitoring telemetri**: posisi (latitude, longitude, altitude), IMU (pitch, roll, yaw), tegangan, arus, dan status GPS.
- **Perhitungan baterai sendiri**: mAh terpakai, sisa persen, dan estimasi waktu terbang. Kapasitas baterai **diisi manual** oleh operator.
- **Penghitung benih**: jumlah dimuat, sudah di-drop, dan sisa.
- **Drop benih** dengan **thrust dan durasi yang bisa diatur**.
- **Riwayat titik drop** (lat, long) untuk ditampilkan di peta.
- **Live preview kamera** (streaming MJPEG).
- **Tes thruster** di darat dan **tombol stop darurat**.
- **Real-time lewat WebSocket**: data status dikirim 5 kali per detik.

## Arsitektur

```
 +-----------+   TELEM (UART)    +--------------------------------------+
 |  Pixhawk  |<----------------->|            Raspberry Pi              |
 +-----------+                   |                                      |
                                 |  MAVProxy --> UDP :14550 ------------+--> Mission Planner (laptop)
                                 |      |                               |
                                 |      +----> UDP :14551               |
                                 |               |                      |
                                 |        Backend FastAPI :8000         |
                                 +---------------+----------------------+
                                                 | REST / WebSocket / MJPEG
                                  +--------------+--------------+
                                  |                             |
                            Web (React)                  Mobile (Flutter)
```

Alur singkat:

1. Pixhawk mengirim data MAVLink lewat port TELEM ke Raspberry Pi.
2. **MAVProxy** membagi data itu ke dua tujuan: Mission Planner di laptop (`udp:14550`) dan backend (`udp:14551`).
3. **Backend FastAPI** membaca data, menghitung baterai dan benih, mengontrol servo drop, dan menyajikan API.
4. **Web** dan **Mobile** terhubung ke backend lewat jaringan WiFi yang sama dengan Raspberry Pi.

## Quick Start

### 1. Siapkan Raspberry Pi

```bash
cd backend
python3 -m venv venv --system-site-packages
source venv/bin/activate
pip install -r requirements.txt
sudo apt install python3-picamera2     # kalau pakai kamera Raspi
pip install mavproxy                   # pembagi data ke Mission Planner
```

> `--system-site-packages` dipakai supaya `picamera2` (terinstall lewat apt) bisa terbaca. Kalau pakai webcam USB, `picamera2` tidak perlu diinstall.

### 2. Sambungkan Pixhawk ke Raspberry Pi

- Kabel dari port **TELEM** Pixhawk ke pin UART Raspi: TX ke RX, RX ke TX, GND ke GND.
- Aktifkan serial di Raspi lewat `sudo raspi-config`, menu Interface Options, Serial Port. Pilih login shell **No** dan serial hardware **Yes**.
- Di Mission Planner, set parameter port TELEM yang dipakai (contoh TELEM2): `SERIAL2_PROTOCOL = 2` dan `SERIAL2_BAUD = 921` (921600).
- Untuk tegangan dan arus, Pixhawk harus memakai **power module** dan `BATT_MONITOR` sudah diset.

### 3. Jalankan MAVProxy

```bash
mavproxy.py --master=/dev/serial0 --baudrate=921600 \
  --out=udp:IP_LAPTOP:14550 --out=udp:127.0.0.1:14551
```

- Ganti `IP_LAPTOP` dengan IP laptop yang menjalankan Mission Planner.
- Di Mission Planner pilih **UDP**, port **14550**, lalu Connect.
- Backend membaca dari `127.0.0.1:14551`.

### 4. Jalankan backend

Di terminal lain di Raspi:

```bash
cd backend
source venv/bin/activate
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Kalau tampil `Pixhawk terhubung!`, berarti berhasil. Alamat MAVLink bisa diganti lewat environment variable `MAVLINK_CONN` (default `udpin:127.0.0.1:14551`).

Setelah berjalan, coba dari laptop (satu jaringan dengan Raspi):

- `http://IP_RASPI:8000/docs`: halaman untuk mencoba semua endpoint dengan klik
- `http://IP_RASPI:8000/status`: semua data monitoring
- `http://IP_RASPI:8000/video`: live preview kamera

### 5. Jalankan web

```bash
cd web
npm install
cp .env.example .env     # isi alamat backend, misalnya http://IP_RASPI:8000
npm run dev
```

### 6. Jalankan mobile

Folder `mobile/` hanya berisi kerangka `lib/`. Folder platform (`android/`, `ios/`) dan `pubspec.yaml` dibuat oleh Flutter:

```bash
cd mobile
flutter create --project-name seeder_drone_app .
flutter pub get
flutter run
```

Alamat backend diatur dari halaman Settings di aplikasi, atau lewat konfigurasi environment di `lib/core/config/`.

## Referensi API

Dokumentasi interaktif tersedia di `http://IP_RASPI:8000/docs`. Ringkasannya:

| Endpoint | Fungsi |
|---|---|
| `GET /status` | Semua data (posisi, IMU, baterai, benih, rata-rata) |
| `WS /ws` | Data yang sama, real-time 5 kali per detik |
| `POST /battery` | Set baterai (**wajib setiap ganti baterai**) |
| `POST /seed/load` | Set jumlah benih yang dimuat |
| `POST /drop/config` | Atur thrust (%) dan durasi (detik) |
| `POST /drop` | Jalankan drop (mengurangi benih, dicatat di riwayat) |
| `POST /thruster/test` | Tes thruster (tidak mengurangi benih, tidak dicatat) |
| `POST /thruster/stop` | Stop darurat thruster |
| `GET /drops` | Riwayat titik drop |
| `GET /video` | Live preview kamera (MJPEG) |

### Contoh pemakaian (curl)

```bash
# Ganti baterai: 6S 16000 mAh
curl -X POST http://IP_RASPI:8000/battery -H "Content-Type: application/json" \
  -d '{"capacity_mah": 16000, "cells": 6}'

# Isi 200 benih
curl -X POST http://IP_RASPI:8000/seed/load -H "Content-Type: application/json" \
  -d '{"loaded": 200}'

# Atur thrust 60% selama 2 detik
curl -X POST http://IP_RASPI:8000/drop/config -H "Content-Type: application/json" \
  -d '{"thrust_percent": 60, "duration_s": 2}'

# Drop!
curl -X POST http://IP_RASPI:8000/drop
```

## Konfigurasi

Pengaturan tersimpan di `backend/data/config.json`:

```json
{
  "battery": { "capacity_mah": 10000, "cells": 6, "min_safe_percent": 25 },
  "drop": {
    "servo_channel": 9,
    "thrust_percent": 70,
    "duration_s": 1.5,
    "seeds_per_drop": 1,
    "pwm_min": 1000,
    "pwm_max": 2000
  },
  "seed": { "loaded": 0, "dropped": 0 }
}
```

| Kunci | Keterangan |
|---|---|
| `battery.capacity_mah` | Kapasitas baterai yang dipasang (diisi manual) |
| `battery.cells` | Jumlah cell (contoh 6 untuk 6S) |
| `battery.min_safe_percent` | Batas aman sisa baterai |
| `drop.servo_channel` | Nomor output AUX di Pixhawk untuk mekanisme drop (default 9). Di Mission Planner set `SERVOx_FUNCTION = 0` untuk channel itu supaya bisa dikontrol manual |
| `drop.pwm_min` / `drop.pwm_max` | Rentang sinyal PWM. Thrust 0% = `pwm_min`, 100% = `pwm_max` |
| `drop.seeds_per_drop` | Jumlah benih yang berkurang setiap kali drop |

## Prosedur Tes Thruster

Tes dulu di darat. **Baling-baling dan pengaman harus sesuai kondisi aman, dan drone tidak boleh dalam keadaan siap terbang.**

1. Pastikan backend sudah menampilkan `Pixhawk terhubung!`.
2. Buka `http://IP_RASPI:8000/docs`, cari **POST /thruster/test**, klik *Try it out*.
3. Mulai dari nilai kecil: `{"thrust_percent": 20, "duration_s": 2}`.
4. Klik *Execute*. Thruster berputar 2 detik lalu berhenti sendiri.
5. Naikkan bertahap (20, 40, 60, dst.) sampai ketemu nilai yang pas, lalu simpan lewat `POST /drop/config`.
6. Kalau ada yang tidak beres, langsung panggil **POST /thruster/stop**.

Batas aman: durasi tes maksimal 10 detik, thrust 0 sampai 100%. Kalau thruster tidak bereaksi, cek `servo_channel` di `config.json` dan pastikan `SERVOx_FUNCTION = 0` untuk channel itu.

Prosedur lengkap ada di `docs/thruster-test-procedure.md`.

## Keselamatan

1. **Lepas baling-baling dan uji mekanisme drop di darat dulu.**
2. **Panggil `POST /battery` setiap ganti baterai**, saat baterai penuh. Itu yang me-reset hitungan mAh terpakai.
3. Hitungan baterai berdasarkan arus dari Pixhawk. Kalau power module belum terkonfigurasi, nilainya kosong (`null`).
4. Kamera hanya bisa dibuka satu proses. Kalau error, pastikan tidak ada program lain yang memakai kamera.
5. Kalau Pixhawk belum terhubung, `POST /drop` akan ditolak.
6. Web dan mobile wajib menyediakan tombol **stop darurat** yang selalu terlihat di halaman tes thruster, dan meminta konfirmasi sebelum drop dijalankan.
7. Ikuti `docs/flight-safety-checklist.md` sebelum setiap penerbangan.

## Catatan Integrasi Web dan Mobile

Beberapa hal yang sering bikin API tidak bisa dipanggil dari aplikasi klien:

- **CORS (web):** backend versi awal belum mengaktifkan CORS. Supaya dashboard React bisa memanggil API dari origin lain (misalnya `localhost:5173`), tambahkan `CORSMiddleware` di `backend/app/main.py` dan batasi `allow_origins` ke alamat yang dipakai.
- **HTTP tanpa HTTPS (mobile):** backend berjalan di `http://`. Android (API 28 ke atas) dan iOS memblokir koneksi cleartext secara default, jadi perlu mengizinkannya di konfigurasi platform (`usesCleartextTraffic` / network security config di Android, App Transport Security di iOS). Batasi hanya untuk jaringan lokal.
- **Live video:** `/video` mengirim MJPEG. Di web bisa dipasang langsung sebagai sumber `<img>`. Di Flutter perlu widget pembaca MJPEG (lihat `features/video/widgets/mjpeg_viewer.dart`).
- **WebSocket:** `/ws` mengirim objek yang sama dengan `GET /status` setiap 0,2 detik. Klien sebaiknya melakukan reconnect otomatis dan menampilkan status koneksi.
- **Nilai `null`:** `voltage` dan `current` bisa `null` kalau power module belum terkonfigurasi. UI harus menangani kasus ini.

## Troubleshooting

| Masalah | Solusi |
|---|---|
| Tidak muncul `Pixhawk terhubung!` | Cek MAVProxy sudah jalan, kabel TX/RX, dan baud rate |
| `voltage` / `current` kosong | Cek power module dan `BATT_MONITOR` di Pixhawk |
| Video tidak muncul | Cek kamera dengan `rpicam-hello`, atau pastikan `picamera2` terinstall |
| Tidak bisa dibuka dari laptop | Pastikan laptop dan Raspi satu WiFi, dan server jalan dengan `--host 0.0.0.0` |
| Web tidak bisa memanggil API | Cek CORS dan alamat backend di `.env` |
| Aplikasi mobile gagal konek | Cek izin cleartext HTTP dan alamat backend di Settings |

Daftar lengkap ada di `docs/troubleshooting.md`.
